# Next.js, Convex, and Vitest

The app is built as a Next.js (App Router) frontend with TypeScript and Tailwind, hosted on Vercel's free tier. Backend, database, and real-time sync are handled by Convex on its free tier — mutations and queries in TypeScript, with reactive subscriptions so the Kiosk Dashboard and live Game views update across clients without managing WebSockets. Domain logic for the Game rules engine and League module lives in pure TypeScript (`lib/game-engine`, `lib/league`) and is tested with Vitest using table-driven tests at the module boundary; Convex mutations call into those modules rather than embedding rules in the database layer.

We chose this stack because the product must feel live — standings, stats, and active Game state updating as Shots are recorded — and Vercel serverless is a poor fit for self-hosted WebSockets. Convex gives reactive queries with minimal backend surface area. Vitest keeps the primary TDD seam (Game rules) fast and framework-free, matching the spec's testing decisions. The alternatives considered were Supabase (Postgres + manual realtime subscriptions, more wiring) and a DIY WebSocket service alongside Vercel (extra hosting, more ops, harder to keep on free tier).
